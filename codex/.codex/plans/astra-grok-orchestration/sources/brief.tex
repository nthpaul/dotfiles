\brieftitle{Astra and Grok: an orchestration plan}{One planner, visible workers, durable communication}{Prepared for Paul \quad | \quad 13 September 2026 \quad | \quad Proposed design}

\textbf{Build a small local runtime controlled by Astra.} Astra owns planning,
delegation, routing decisions, and acceptance. Grok workers execute bounded tasks
and report only to Astra. Runtime code handles persistence, delivery, and process
monitoring without consuming a model turn for routine bookkeeping.

Keep two logical structures: \textbf{current state} and \textbf{append-only history}.
Inboxes and the bulletin are views over them. Central supervision is an established
pattern [\hyperref[s1]{1}]; these particular schemas and guarantees are proposals.
Live transport, interruption, and recovery must pass the implementation gates on page 6.

\section*{Data structures and ownership}
\textbf{Stable IDs outlive processes.} Keep \texttt{worker\_id}, \texttt{task\_id},
and \texttt{run\_id} distinct. A task may be reassigned; a worker may restart; a pane
may be reused. PID, process start identity, pane ID, and Grok session ID are handles,
not primary keys. A retry creates a new run and retains the old history.

\textbf{Write contract.} The runtime atomically appends the event, changes affected
state, and inserts pending deliveries before returning a durable receipt. SQLite
provides transactional isolation with serialized writers [\hyperref[s3]{3}].
Agents use the CLI/API; they do not rewrite a shared JSON document. JSON remains
the inspection/export format. Artifact files are finalized and hashed before their
references are committed; incomplete or missing artifacts cannot satisfy acceptance.

\section*{Message schema and delivery contract}
\textbf{Structured metadata; free-form explanation.} The example below is a
persisted event, not a delimiter-based string. The runtime assigns event IDs,
team sequence numbers, timestamps, and validated sender identity. Workers supply
the report and suggested recipients; only Astra can authorize forwarding.

  "event_id": "evt-0042",
  "team_id": "auth-upgrade",
  "sequence": 42,
  "timestamp": "2026-09-13T14:05:00Z",
  "type": "plan_conflict",
  "from": "worker-auth",
  "run_id": "run-017",
  "to": "orchestrator",
  "task_id": "task-auth-api",
  "plan_revision": 3,
  "priority": "urgent",
  "suggested_recipients": ["worker-ui", "worker-tests"],
  "body": "The contract cannot represent partial success.",
  "artifact_refs": ["artifact-contract-v2"],
  "reply_to": null
}
\end{lstlisting}

\begin{tabularx}{\linewidth}{@{}>{\raggedright\arraybackslash}p{32mm}>{\raggedright\arraybackslash}p{31mm}Y@{}}
\toprule\textbf{Message} & \textbf{Direction} & \textbf{Meaning}\\\midrule
Assignment & Astra to worker & Task, scope, dependencies, revision, acceptance criteria.\\
Progress / result & Worker to Astra & Store progress quietly; a result enters review.\\
Question / conflict & Worker to Astra & Track unresolved issue; priority can be urgent.\\
Proposal & Worker to Astra & Suggest recipients and attach an artifact reference.\\
Publication & Astra to workers & One delivery per selected recipient; retain source event.\\
Pause / resume / cancel & Astra to runner & Track requests separately from confirmed outcomes.\\
\bottomrule
\end{tabularx}

\textbf{Four distinct facts.} A \emph{receipt} confirms durable storage.
\emph{Delivered} means the adapter submitted the message to the session.
\emph{Acknowledged} means the recipient accepted that message ID, confirmed by the
protocol or explicit worker response. \emph{Resolved} means the question or requested
action has an outcome. Acknowledgment never proves task completion. Established
messaging systems make the same receipt/processing distinction [\hyperref[s4]{4}].

Each mutation carries a request ID. An identical retry returns the same receipt;
changed content with the same ID is rejected. Delivery retries reuse the message ID
and recipients deduplicate. Track delivery per recipient, not only a high-water
timestamp: urgent processing may skip older normal messages. Sequence numbers
record commit order, not a guarantee of causal order between independent workers.

\textbf{Context contract.} Each assignment includes the objective, relevant plan
decisions, expected output, acceptance checks, and exclusive write scope. Workers
return findings, artifact references, validation evidence, and unresolved issues.
Astra retrieves history selectively after compaction instead of rereading all logs.

\section*{Urgent messages and recovery}
\textbf{Priority changes scheduling, not storage order.} The override inbox is the
urgent unresolved view. It is checked before normal messages; repeated reports of
the same issue are coalesced. An urgent flag alone cannot interrupt a model turn or
stop an executing tool. The transport adapter must establish those capabilities.

\toprule\textbf{Failure or race} & \textbf{Required behavior}\\\midrule
Old-plan result arrives & Preserve it with its assignment revision. Astra checks changed dependencies before accepting or requesting revision.\\

\bottomrule
\end{tabularx}

\textbf{Recovery ownership.} One active coordinator session controls a team. An
ownership epoch rejects stale-session commands after takeover. Record execution
intent before launching a process and observed outcome afterward; reconcile
incomplete intents on restart. Durable history remains outside the agent's context,
consistent with the recovery principle in [\hyperref[s2]{2}].

\textbf{Independent states.} Tasks move from queued to running to awaiting review
to accepted, with blocked, failed, and cancelled outcomes. Run health is starting,
running, unresponsive, or exited. Pause/cancel requests are control states with
separate confirmation. A live PID does not imply useful progress or completed work.

\section*{Delivery plan, tmux rules, and decision gates}
\textbf{First milestone: two tasks and one revision in a single window.} Astra delegates two tasks, receives results, requests one revision, and accepts
the combined outcome. Also demonstrate restart recovery and an urgent replan.

\begin{tabularx}{\linewidth}{@{}>{\raggedright\arraybackslash}p{8mm}>{\raggedright\arraybackslash}p{35mm}Y@{}}
\toprule & \textbf{Atomic stage} & \textbf{Exit evidence}\\\midrule
1 & Transport spike & Launch, stream, acknowledge, follow up, resume, and cancel one Grok run. Wake the exact Astra session; document unsupported behavior.\\
2 & Store + pane lifecycle & Stable IDs, transactional events and deliveries, pane ownership, reuse, and tiling. No lost concurrent events or wrong-pane cleanup.\\
3 & Routing + recovery & Normal/urgent inboxes, bulletin fan-out, deduplication, takeover, and stale-result checks. Recover at each delivery boundary.\\
4 & Skill + integration & Astra/Grok role contracts, isolated worktrees, acceptance review, and a CI-passing Graphite stack. Complete the first milestone.\\
\bottomrule
\end{tabularx}

\textbf{Pane contract.} Proposed default: the orchestrator's existing tmux window,
with a separate pane per agent and a visible runtime/status pane. Register exact server, window, and pane IDs. Reuse idle team-owned panes;
otherwise split and run \texttt{select-layout tiled}, the action already bound to
Ctrl-b then \texttt{t}. Preserve focus; cleanup only the worker pane. Queue work when the screen is full.
Verify process start identity before signaling a PID. Reuse sessions for related work;
start fresh sessions for unrelated work.

\textbf{Code ownership.} One current executing attempt per task; isolated worktrees
for concurrent writers. One named integration worker assembles accepted changes.
Use \texttt{gt create} and \texttt{gt submit --no-interactive}; every PR must
independently pass required CI. Publication stays within the task's authorization.

\textbf{Open choices and local evidence.} Recommend a live runner activity view
with steering commands; full Grok TUI remains an open choice. Start with two workers.
Installed Grok 1.0.30 advertises streaming JSON; Codex 0.154.0 advertises
\texttt{queue}. Interruption semantics remain untested. Existing \texttt{orch}
creates and kills separate windows; reuse selectively. Omit its mandatory
\texttt{poteto-mode} and nested agents. Resolve the missing documented \texttt{wt}
script path before code tasks.

\textbf{Required fault tests.} PID reuse; crash before send and after send/before ack;
duplicate assignment; urgent conflict during a tool call; old-revision result;
coordinator takeover. Measure urgent acknowledgment latency, recovery time, failed
deliveries, and coordination turns before increasing concurrency.
